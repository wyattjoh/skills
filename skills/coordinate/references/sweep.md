# Sweep verdicts

`coordinate sweep report` reads every linked worktree of the domain's repos (`.claude/worktrees` included), landed branches, processes in deleted worktree folders, stale `.scratch` entries, and base checkouts ahead of their remote. It changes nothing. Herdr core's own processes (`hc` or `herdr-core` run with `--hc-launchd`, `hold` or `connect`, and the launchd server's ssh children) hold live terminals, so the report never counts or lists them. A process an ended delegate provably left in its worktree (its working folder is inside the worktree, and so is every ancestor's up to launchd, so no live terminal, editor or shell started it) is tied to that delegate: the row names it, and it does not make the row ASK.

| Verdict | Meaning                                                                                                                                          | What you do                                                                                                                                                                               |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SAFE    | Work is on a base (fast-forward, merge, rebase or squash) or its PR merged; nothing uncommitted, no session, no process but its ended delegate's | Remove it in the same turn: `coordinate sweep remove <worktree>` (or `--all-safe`); `prune-branches <repo> <branch>...` for landed branch rows; `kill <pids>` for its own stray processes |
| CLOSE   | Finished, but a session still runs there                                                                                                         | `coordinate end <name>` for your delegate, then remove; a session the user started is theirs: tell them                                                                                   |
| ASK     | Work would be lost: uncommitted files, unpushed unlanded commits, a detached head, processes not tied to an ended delegate, stale scratch        | One ask per row in the next batch, naming what would be lost; never remove on your own                                                                                                    |
| KEEP    | In use: an open PR, a live session with changes, a base branch, unfinished work                                                                  | Nothing                                                                                                                                                                                   |
| INFO    | A base checkout ahead of its remote, or PRs that could not be read                                                                               | Mention it when it matters to the user's next decision                                                                                                                                    |

`remove` recomputes the verdict and keeps anything not SAFE. It first stops the ended delegate's tied processes (SIGTERM, three seconds, then SIGKILL, re-reading each pid so a reused one is never signalled), prints each pid and command, and keeps the worktree when one survives. It parks `.scratch/` under `<main>/.scratch/parked/<name>`, drops build output and other ignored files, deletes the branch with `git branch -d`, closes the delegate's space and prunes its ended record. It prints "removed N of M" with why each was kept. `--all-safe` also stops the processes an ended delegate left in a deleted worktree folder; other processes in deleted folders keep their `kill` hint.

When `git branch -d` refuses (a squash or rebase merge), the output prints the `git branch -D` command: give it to the user to run, and run nothing stronger yourself.

`coordinate sweep prune-ended` deletes ended-delegate records whose worktree is gone. Run `remove --all-safe` first: without its record, a delegate's processes in a deleted folder are no longer tied to it.
