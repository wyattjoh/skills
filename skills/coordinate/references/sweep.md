# Sweep verdicts

`coordinate sweep report` reads every linked worktree of the domain's repos (`.claude/worktrees` included), landed branches, processes in deleted worktree folders, stale `.scratch` entries, and base checkouts ahead of their remote. It changes nothing. Herdr core's own processes (`hc` or `herdr-core` run with `--hc-launchd`, `hold` or `connect`, and the launchd server's ssh children) hold live terminals, so the report never counts or lists them. A process an ended delegate provably left in the worktree `delegate --repo` made for it (its working folder is inside the worktree, and so is every ancestor's up to launchd, so no live terminal, editor or shell started it) is tied to that delegate: the row names it, and it does not make the row ASK.

| Verdict | Meaning                                                                                                                                          | What you do                                                                                                                   |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| SAFE    | Work is on a base (fast-forward, merge, rebase or squash) or its PR merged; nothing uncommitted, no session, no process but its ended delegate's | Remove it in the same turn: `coordinate sweep remove <worktree>` (or `--all-safe`); `kill <pids>` for its own stray processes |
| CLOSE   | Finished, but a session still runs there                                                                                                         | `coordinate end <name>` for your delegate, then remove; a session the user started is theirs: tell them                       |
| ASK     | Work would be lost: uncommitted files, unpushed unlanded commits, a detached head, processes not tied to an ended delegate, stale scratch        | One ask per row in the next batch, naming what would be lost; never remove on your own                                        |
| KEEP    | In use: an open PR, a live session with changes, a base branch, unfinished work                                                                  | Nothing                                                                                                                       |
| INFO    | Landed branches kept locally, a base checkout ahead of its remote, or PRs that could not be read                                                 | Nothing for landed branches; mention the rest when it matters to the user's next decision                                     |

`remove` recomputes the verdict and keeps anything not SAFE. It first stops the ended delegate's tied processes (SIGTERM, three seconds, then SIGKILL, re-reading each pid so a reused one is never signalled), prints each pid and command, and keeps the worktree when one survives. It parks `.scratch/` under `<main>/.scratch/parked/<name>`, drops build output and other ignored files, tries `git branch -d` on its branch, closes the delegate's space and prunes its ended record. It prints "removed N of M" with why each was kept. `--all-safe` also stops the processes an ended delegate left in a deleted worktree folder; other processes in deleted folders keep their `kill` hint.

When `git branch -d` refuses (a squash or rebase merge), the line reads `kept branch <branch> <sha>`. Leave the branch: landed branches cost nothing, so the coordinator neither deletes them nor asks the user to. `coordinate sweep prune-branches <repo> [--list] [<branch>...]` lists or `-d`-deletes them when the user asks for it.

## Remote worktrees

The report also judges the linked worktrees of each checkout the domain's Boundary records on another machine (`backlog boundary add <repo> --machine <m> --checkout <path>`). Git, sessions and processes are read on that machine through `hc exec`, against that checkout's own bases, and rows carry machine-qualified paths such as `strix:/home/me/app/.claude/worktrees/fix-a`. A machine that does not answer gets one INFO row and none of its worktrees are judged; a worktree whose processes cannot be read there is never SAFE. Landed-branch, stale-scratch, ahead-of-remote and deleted-folder rows cover checkouts on this machine only.

A branch you fetched and landed on this Mac counts as landed when its exact tip commit is on a base of the matching repo here (the owned Boundary path whose checkout map holds that checkout): the row reads SAFE with `tip on <base> on this Mac`. A tip that reached this Mac's base by squash or rebase is a different commit, so that worktree stays ASK until the remote checkout has the work. A worktree whose folder is gone on its machine reads ASK with `folder gone on <machine>`.

`coordinate sweep remove <machine>:<path> [--domain d]` removes a SAFE remote worktree on its machine, only when it is a linked worktree of a checkout that Boundary records there. It stops the ended delegate's tied processes there, copies the worktree's `.scratch/` to `<repo>/.scratch/parked/<name>/` on this Mac (and keeps the worktree when that copy fails), runs `git worktree remove` and `git branch -d` on the machine, closes the delegate's space and prunes its ended record. When `-d` refuses, the branch stays (it always refuses for a branch landed only on this Mac, since the remote's base lacks its commits). coordinate never forces the delete. `--all-safe` includes remote SAFE rows.

`coordinate sweep prune-ended` deletes ended-delegate records whose worktree is gone: a remote record's folder is checked on its own machine, and a record whose machine does not answer (or whose machine is unknown because this core's Herdr name is unreadable) is left in place and listed. Run `remove --all-safe` first: without its record, a delegate's processes in a deleted folder are no longer tied to it.
