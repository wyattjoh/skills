# Drive runs from a detached workflow runtime

A long-lived Engine in its own Herdr tab executes the run's workflow script, launches and prompts every agent, runs gates, reads agent reports from exact files, and lands tickets. The coordinator only starts the Engine, reads its append-only event log through a bounded cursor wait, and answers escalations, so harness tool-call limits, compaction, and coordinator restarts never interrupt ticket progress. RESUME.md stays the only mutable coordination state: built-in workflow steps converge on the effect they find recorded there and in immutable evidence rather than replaying a second journal, and only custom steps store write-once results. An Engine Lease with a generation compare-and-swap fences every write so a superseded Engine cannot mutate the run. The serialized finalization slot is removed: gates and both reviews run per ticket in parallel, implementors rebase their own branches in their own worktrees, and landing holds the shared `land-local.lock` only for the ancestor check and `git merge --ff-only`. After a rebase every gate reruns, but both reviews are reused when the ticket's patch identity is unchanged; this accepts that an identical diff on a moved base keeps its prior semantic review, relying on gates to catch integration breakage. The cost is a second supervised process, a determinism contract for workflow scripts, and a schema-2 RESUME.md that refuses schema-1 runs.
